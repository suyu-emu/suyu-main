# suyu v0.0.14

This candidate repairs startup and export-dialog shutdown crashes and adds an
Ubuntu 24.04 x86-64 AppImage alongside the existing Linux tarball.

## Startup and export fixes

- HID timing callbacks start after their motion samplers are constructed. This
  prevents a callback from accessing an uninitialized console motion sampler.
- Closing the main window stops and joins game-list population before its
  provider and system owners are destroyed. Queued reloads cannot restart a scan
  during shutdown. A Source-export close sequence that reproduced an access
  violation now exits normally in a matched-runtime test.
- Source exports use a fixed CMake project name. Game titles containing spaces,
  Unicode or CMake special characters no longer become project arguments.
- The build label follows the exact release tag instead of displaying v0.0.11.
  Later development commits retain their own commit and branch identity.
- The export cache revision advances so fresh exports rebuild their host with
  the startup fix. **Re-export existing Static and Hybrid packages**: their
  executables contain an embedded host that updating the GUI does not replace.

## Linux AppImage

The new `suyu-linux-x86_64.AppImage` bundles the GUI, command frontend and their
runtime libraries. The supported packaging target is Ubuntu 24.04 x86-64.

```sh
chmod +x suyu-linux-x86_64.AppImage
./suyu-linux-x86_64.AppImage
./suyu-linux-x86_64.AppImage --suyu-cmd --help
```

For an environment without FUSE, extract the package and launch its entrypoint:

```sh
./suyu-linux-x86_64.AppImage --appimage-extract
./squashfs-root/AppRun
```

The Linux `.tar.gz` remains available. An additional
`suyu-v0.0.14-appimage-sources.tar.gz` records corresponding sources for the
AppImage runtime and bundled system libraries. Licenses and notices are included
inside the image. The project and existing dependency-source archives continue
to accompany the release.

The release pipeline inspects the final embedded SquashFS filesystem, validates
the runtime and source receipts, and requires extraction, command-help and
offscreen GUI startup checks. The source and payload checks reject keys,
firmware, game containers, game exports and user data.

## Verification status

The HID publication regression, five Static smoke variants and 111 export
integration checks pass. Matched-runtime Source-export shutdown tests reproduce
the access violation before the GUI fix and a normal exit after it. The runtime
build is reproducible, and real SquashFS policy tests include forbidden-content,
unsafe-link and malformed-image cases.

Windows strict Static playtests on the repaired code passed the following bounded
scenarios, with rendered screenshots, input response, zero JIT transitions and
clean exits:

| Game | Version | Reviewed gameplay | Mean sampled gameplay FPS |
| --- | --- | --- | --- |
| Mario Kart 8 Deluxe | 4.0.0 | Mario Kart Stadium opening race, 6001-frame replay | 60.00 |
| Super Mario Odyssey | 1.3.0 | Cap Kingdom, running, jumping and landing | 59.46 |
| Tears of the Kingdom | 1.4.3 | Beneath Hyrule Castle cave, forward movement | 29.90 |
| Xenoblade Chronicles 3 | 1.0.0 | Opening combat and Everblight Plain movement | 29.72 |

These are functional playtests, not full playthroughs or paired performance
benchmarks. Gameplay means include their observed stalls; startup and loading
samples are recorded separately. The final MK8D race interval created no new
pipelines. Other sessions retained shader-compilation activity. Earlier input
setup and tutorial-navigation failures were preserved, and inputs blocked by a
tutorial were not counted as movement evidence.

Platform release CI and final package validation remain required before publication.
